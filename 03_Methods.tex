\section{Study 1: Phylo2Vec}
The overarching goal of \gls{p2v} (or Phylo2Vec)~\cite{penn2025, scheidwasser2025} is to encode phylogenetic tree topology into an integer-based vector format. Inspired by Yule processes~\cite{steel2001} and tree counting strategies~\cite{knuth1973, rotem1978, proskurowski1980, rohlf1983}, the core idea of the vector is to describe \emph{where} leaves are iteratively added to an existing tree topology. The construction of phylo2vec takes inspiration from the work of Rohlf~\cite{rohlf1983}, but differs in its edge labelling strategy and, most importantly, its preservation of the tree construction process as a vector. Beyond this conceptual shift, we contribute four key advances: (i) rigorous proofs of the bijectivity of the vector representation to the space of binary rooted trees~\cite{penn2025}, (ii) an extended matrix format to incorporate branch length information, (iii) empirical evidence of its potential utility for phylogenetic inference, and (iv) robust and open-source software for its utilisation for manipulating phylogenetic trees~\cite{scheidwasser2025}.

The simple constraint of the phylo2vec formulation notably allows for rapid tree sampling, efficient compression, and trivial comparison of tree topologies. In addition, the simplicity of such a vector format makes it a convenient starting object for phylogenetic tree manipulation. This is showcased in a recent software package~\cite{scheidwasser2025}, which also highlights its potential for phylogenetic inference, including non-traditional optimization approaches such as GradME (gradient-based balanced minimum evolution)~\cite{penn2023}.

\subsection{Definitions}
\emph{Phylo2Vec} denotes a bijective mapping of phylogenetic tree topology into a constrained integer vector. It relies on the following assumptions on tree topology construction:

\begin{itemize}
    \item Let $n$ $T$ be a binary, rooted, phylogenetic tree with $n \geq 2$ leaves and topology $\tau$.
    \item Each leaf is assigned a unique label $\ell \in \{0, \ldots, n-1\}$.
    \item Each internal node is assigned a unique label $\ell' \in \{n-1, \ldots, 2(n-1)\}$. Their ordering generally depends on their height and descending leaves (see~\ref{methods:v2newick}). The root node is always labelled $2(n-1)$.
    \item Each branch (or edge) is labelled according to their target node (i.e., a branch leading to node $\nu$ is labelled $\nu$).
\end{itemize}

Figure~\ref{fig:p2vtree} depicts an example tree which satisfies these assumptions. Consequently, for any $n$-leaf tree topology, we define an integer vector representation $\boldsymbol{v}$ of length $n-1$:

\begin{equation}
    \forall n \geq 2 \quad \forall j \in \{0, \ldots, n-2\} \quad v_j \in \{0, \ldots, 2j\}
    \label{eq:p2v}
\end{equation}

In this formulation, $v_j$ denotes the \emph{edge} from which leaf $j + 1$ descends when added to a tree with $j$ leaves. An immediate property that arises from Eq.~\ref{eq:p2v} is that the set of phylo2vec vectors has the same cardinality as the set of binary rooted trees~\cite{cavallisforza1967}. Noting $\mathbb{V}_n$ and $\mathbb{T}_n$ as, respectively, the set of vectors and binary trees with $n$ leaves:

\begin{equation}
    |\mathbb{V}_n| = \prod_{j=0}^{n-2}(2j+1) = 1\cdot3\cdot\ldots\cdot2n-3=(2n-3)!! = |\mathbb{T}_n|
    \label{eq:p2v_cardinality}
\end{equation}

Given Eq.~\ref{eq:p2v_cardinality}, showing that there exists an injection from $\mathbb{V}_n$ to $\mathbb{T}_n$ for any $n \geq 2$ is sufficient to demonstrate bijectivity between both sets. A proof is provided in Penn \textit{et al.}~\cite{penn2025} (see~\ref{appendix:articles}).

A Phylo2Vec vector is said to be \textit{ordered} if it satisfies:

\begin{equation}
    \forall n \geq 2 \quad \forall j \in \{0, \ldots, n-2\} \quad v_j \in \{0, \ldots, j\}  
    \label{eq:p2v_ordered}
\end{equation}

The term \textit{ordered} refers to the fact that any leaf $i$ will, in a similar vein to Yule processes, rises from an ``older" leaf $j < i$. The cardinality of ordered trees is $\prod_{j=0}^{n-2}(j+1) = (n-1)!$. Whilst a (small) subset of all phylo2vec vectors, ordered trees are more algorithmically efficient to manipulate (see~\ref{methods:v2newick} and~\ref{methods:newick2v}) and more practical some for downstream phylogenetic applications~\cite{penn2023, penn2025}. Importantly, the \emph{Queue Shuffle} trick (see \textcolor{red}{section})~\cite{penn2023} enables the transformation of any \emph{unordered} vector $\boldsymbol{v}$ into an ordered one.

Unrolling a vector to a tree occurs in several steps (see Figure~\ref{fig:v2newick} for a full illustration). First, we form a list of "pairs", a 2-tuple where the first element is a numbered branch, and the second element is the leaf to be added. To fill the list, we devised the following algorithm: \textcolor{red}{algorithm}. A naive implementation using insert operations for "unordered" nodes and append operations for "ordered" nodes has a best-case complexity of O(n) (all append), average complexity of O(n$^{1.5}$), and worse-case complexity of O(n$^2$) (all insert). An optimized implementation makes use of Adelson-Velsky and Landis trees (AVL), where insert operation are O(log n), thus result in an O(n log n) best, average, and worst-case complexity.

From this list of pairs, we build a second intermediary object called an "ancestry" matrix, which consists in a list of cherries, described in (child1, child2, parent) triplets. From there, we can build a Newick string by iteratively merging Newick substrings fro the ancestry matrix. The ancestry matrix can be viewed as some sort of post-order traversal, and shares similarities with the "operations" object in BEAGLE.
